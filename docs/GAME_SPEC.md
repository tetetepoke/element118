# ELEMENT 118 — GAME SPEC

## 基本コンセプト
3D三人称探索アクションADV。
主人公カーボンが地下世界を探索し、さまざまな元素と出会う。

元素の性質を、探索・採取・環境変化・道具・障害物・戦闘・謎解きなどへ利用する。

単なる元素暗記ゲームにはしない。
遊んでいるうちに「この元素にはこんな性質がある」と自然に理解できるゲームを目指す。

## 主人公
- 名前：Carbon / カーボン
- 元素：C
- 原子番号：6

外見の基本：
- 黒系の乱れた髪
- 白いC/6のお面（角のような特徴あり）
- クリーム色系の傷んだマント／スカーフ
- ベルト、ポーチ、ブーツ、サッチェル
- 青く光るペンダント

性格は少し恥ずかしがり屋。
（見た目の詳しい基準：`docs/CHARACTER_DESIGN.md`、正式な基準画像：`art/reference/character-design-reference.png`）

## BOND
元素同士を必要なときに結合させる中核システム。
BONDすると、見た目・能力・属性・移動能力・環境への作用などが変化する。

ただし「元素A＋元素Bなら何でも単純に化合物ABになる」という誤った表現は避ける。
ゲーム表現と実際の科学を区別する。

## BREAK
BOND状態を解除し、必要に応じて元素を分離する。
BONDとBREAKを使い分けて探索する。常に結合していることが正解ではない。
「必要なときにつながり、必要なときに離れる」という考え方もゲーム全体のテーマにつなげる。

## SiCフォーム
C + Si による重要フォーム。SiC（炭化ケイ素）の性質をゲーム能力へ反映する。

用途例：
- 硬い障害物への対応
- 岩などの破壊
- 耐熱性を利用する場所

Stage 2「珪晶の谷（Si編）」で重要になる。

## 探索
元素の実際の性質を利用して道を開く。
単純な「赤＝火」「青＝水」だけの属性ゲームにはしない。
元素や物質の性質から「この性質なら突破できるかもしれない」とプレイヤー自身が考えられる設計を目指す。

## 元素図鑑
発見した元素・物質などを図鑑へ登録する。
図鑑ではゲーム能力だけでなく、実際の科学的情報も学べるようにする。
科学的事実とゲーム内の架空設定を区別して表示する。

## 第一の窪地
序盤の探索エリア。
目的：「脱出するための道を探す」

基本的な流れ：
- 周囲を探索
- 青く光るものを調べる
- 必要な元素を探す
- 元素能力を利用する
- 道を開いて先へ進む

地形には、窪地・水・滝・遺跡・湖・青く光る構造物などが存在する。
ここで3D探索の基本を覚える。

## 珪晶の谷
Stage 2。Siを中心としたエリア。
H、O、Siなどとの関係がゲームシステムとして広がる。

- C + Si → SiCフォーム
- BREAK → CとSiへ分離

という使い分けを学ぶ。（2D版の実装方針：`docs/STAGE2_PLAN.md`）

## 3D移動
三人称視点。プレイヤーは3D空間を自由に探索する。

特に重要なのは衝突判定。
プレイヤーが壁・岩・建物・地形・大型オブジェクトなどへめり込まないようにする。
コライダーは見た目とできるだけ一致させる。必要以上の「見えない壁」を作らない。

## カメラ
カメラアングルは固定しない。プレイヤー自身が自由にカメラを回転できるようにする。
- スマートフォン：右側3Dスティック
- コントローラー：右スティック

条件：
- 滑らかに回転する
- 急激に飛ばない
- プレイヤーを見失わない
- 壁の内部へ入りにくい
- プレイヤーの移動方向との関係が自然（移動はカメラの向きが基準）

## スマートフォン操作
- 画面左：3D仮想スティック → プレイヤー移動
- 画面右：3D仮想スティック → カメラ操作（左右同時に操作できる）

必要なアクション：BOND／BREAK／JUMP／調べる・決定

UIでゲーム画面を隠しすぎない。

## コントローラー
Gamepad API対応。Nintendo Switch Pro Controllerを含む一般的なゲームパッドで操作できる構造を目指す。

基本：
- 左スティック：移動
- 右スティック：カメラ
- 各種ボタン：JUMP / BOND / BREAK / 決定など

スマートフォン操作とコントローラー操作を共存させる。
入力は InputManager（`src3d/core/input.ts`）に集約し、ボタン割り当ては `src3d/core/inputConfig.ts` で変える。
（現在の割り当て一覧：`docs/CHAPTER1.md` の「操作」）

## UI
基本的に必要なもの：
- HP／状態表示
- ミニマップ
- BOND / BREAK / JUMP
- 左仮想スティック / 右仮想スティック
- インベントリ
- 元素図鑑
- メニュー

ゲーム画面の視認性を優先する。

## 3D素材
現段階ではキャラクターや物体の3Dモデルは仮素材でもよい。
今は、探索・操作・カメラ・当たり判定・BOND/BREAK・ステージ進行・ストーリーを実際に遊べる状態にすることを優先する。
正式3Dモデルへ後から簡単に交換できる構造にする（見た目とゲームの判定を分ける）。

## 開発優先順位
1. ゲームが正常に動く
2. 移動が気持ちいい
3. カメラが使いやすい
4. 当たり判定が自然
5. 探索が面白い
6. BOND/BREAKが面白い
7. 科学として納得感がある
8. グラフィックを仕上げる

見た目だけを先に完成させない。
